Who this helps

Three audiences, one contract.

ReddiAgent uses ADL as the source of truth, then shows each audience the question they actually need answered.

Builder

Build from the harness, not a vendor script.

Start with the job, model needs, tools, data, policies, eval gates, traces, and optional payment metadata. The demo shows simple, tool-using, and payment-metadata agents moving through review without hiding unsupported paths.

Maintainer

See what your target preserves.

Frameworks and provider formats become compatibility targets, not the source of truth. The matrix makes loss visible across Agent Spec, A2A Agent Card, Agent Skills, provider reports, RAP bridge metadata, and Vercel eve states.

Reviewer

Review claims before runtime.

Operator surfaces show pinned evidence, boundary flags, dry-run transcripts, rollback cues, and fail-closed cases. Risky fields stay review-only until a bounded lane proves they are safe to activate.

The story

Most agent demos start too late.

They show something running before anyone can inspect permissions, target loss, rollback posture, or denial logic. This demo starts earlier: before runtime, before integrations, before money moves.

1

2

3

See whether each target is report-ready, metadata-only, blocked before generation, or blocked by validation.

4

Review

Use pinned evidence, dry-run transcripts, rollback cues, and boundary flags to decide what can safely move next.
