# ADL v0.2.0-beta is out — and there's an arena where you can fight it

_Published alongside the `v0.2.0-beta` GitHub release. Canonical links:
[spec](https://agent-protocol.reddi.tech/spec) ·
[release](https://github.com/nissan/reddiagent-lab/releases/tag/v0.2.0-beta) ·
[feedback](https://agent-protocol.reddi.tech/feedback) ·
[Reddi Arena](https://reddi-arena-production.up.railway.app)_

Today we're publishing the first public release of the **Agent Definition
Language (ADL) v0.2.0-beta** — an open specification for describing an AI agent
completely, portably, and verifiably: the model envelope it needs, the harness
it runs in (tools, data, memory, policies, eval gates), and optionally the
payment and reputation contract it operates under.

## Why this exists

USENIX Security 2026 (arXiv:2607.19545) found security-rule violations in all
fifteen major x402 payment facilitators. The endemic failure mode is simple:
**"payment succeeded" gets treated as "the work was done."** ADL and the Reddi
Agent Protocol exist to make that conflation impossible — an agent's
declaration is a contract, receipts carry evidence of work rather than just
settlement, and a validator can check all of it deterministically, offline,
with no wallet anywhere near the loop.

## What you get in the beta

- **The canonical spec + JSON Schema** — 37 definitions, closed vocabularies,
  fail-closed extension handling, and a five-level conformance ladder (L0
  parse-clean through L4 fully-verified). A migration guide covers v0.1
  documents.
- **A receipt-integrity validator** that enforces ten evidence layers against a
  fourteen-case threat model (replay, wrong-payee, paid-but-denied, authority
  misuse). It survived three rounds of adversarial review — 33 attack probes,
  every one failing closed.
- **16 validated examples**, including both sides of an agent-to-agent paid
  delegation at conformance Level 3 — buyer and seller — on the honest dry-run
  rail. Plus 20+ negative fixtures any correct validator must reject.
- **Tooling**: conformance checker, diagnostics, provider compatibility reports
  (OpenAI, Anthropic, Gemini, Ollama, LangGraph), A2A Agent Card export, and a
  222-test deterministic suite.

Code is Apache-2.0; specs and docs are CC BY 4.0. Live settlement and mainnet
remain explicitly gated behind an external audit — everything here runs on the
dry-run rail by design.

## The spec has a proof: Reddi Arena

Specs earn trust by being implemented by someone with an incentive to break
them. So we built one — a game.

**[Reddi Arena](https://reddi-arena-production.up.railway.app)** is a
competitive homebrew-bot arena where every game mechanic is a protocol surface:

- your **bot** is an ADL document — the schema is the garage;
- your **weight class** is computed from the declaration, so lying about your
  loadout is a validation failure, not a house rule;
- the **league tiers** are the five conformance levels — you climb the spec
  ladder by playing;
- the **mercenary market** where you hire power-up specialists is RAP
  discovery ("relevance is not trust");
- the **purse** is escrow + receipts, and match adjudication is an eval gate —
  transport success is never task success.

Thousands of adversarial players trying to get paid without doing the work is
the best conformance suite a payments protocol can have. A leaderboard is a bug
bounty people *want* to enter.

The Arena is live on the dry-run rail (prizes are ARENA-CREDIT) and
**accepting early-access waitlist signups now** at
[reddi-arena-production.up.railway.app](https://reddi-arena-production.up.railway.app).

## The beta already found real spec gaps — help us build v0.3

Building the Arena against v0.2.0-beta produced genuine findings, filed
publicly the way we want all feedback filed:

- **No price-discovery field**
  ([#440](https://github.com/nissan/reddiagent-lab/issues/440)): `maxAmount` is
  a spending cap, not a quoted price. A marketplace card cannot say "this
  specialist costs 20 per task" in canonical ADL — the Arena had to invent a
  local extension for the one number a discovery UI most needs standardized.
- **Currency enum excludes non-monetary units**
  ([#441](https://github.com/nissan/reddiagent-lab/issues/441)): points,
  credits, and in-game currencies can't be expressed, which any dry-run or
  gamified economy needs.
- **Seller-side `charge` intents escape the authority envelope**
  ([#389](https://github.com/nissan/reddiagent-lab/issues/389)): the rigor the
  schema demands of `spend` and `refund` intents is not required of `charge`
  intents — with ablation evidence attached.

These three issues are the seed of the **ADL v0.3 backlog**, and this is the
open call: **if you build against the beta and hit a wall the spec should have
prevented, that report is a v0.3 design input.**

The highest-value feedback is an implementation report, not an opinion. File it
with the
[open-spec review template](https://github.com/nissan/reddiagent-lab/issues/new?template=open-spec-review.md),
or start at [agent-protocol.reddi.tech/feedback](https://agent-protocol.reddi.tech/feedback).

## Get started in five minutes

```bash
# grab the bundle
curl -LO https://agent-protocol.reddi.tech/downloads/adl-v0.2.0-beta.zip
unzip adl-v0.2.0-beta.zip && cd adl-v0.2.0-beta

# validate an example
python3 scripts/adl_v02_conformance.py examples/v0.2/payment-agent.yaml
```

Then pick your path:

- **Spec reviewers** → [agent-protocol.reddi.tech/spec](https://agent-protocol.reddi.tech/spec)
- **Builders** → [github.com/nissan/reddiagent-lab](https://github.com/nissan/reddiagent-lab) (`CONTRIBUTING.md`)
- **Players** → [join the Reddi Arena early-access waitlist](https://reddi-arena-production.up.railway.app)

v0.3 gets built from what you break.
