# ReddiAgent Glossary

_Loop 19. Anchor issue: #20._

## Terms

| Term | Meaning |
|---|---|
| Agent | Model plus harness plus optional extensions. |
| ModelProfile | Capability and constraint description for model selection. |
| Harness | The operating environment around the model. |
| Tool | External action with typed input/output. |
| Function | Bounded callable capability, often a tool implementation. |
| Skill | Reusable capability bundle. |
| DataSource | Knowledge or data the harness can access. |
| Memory | State retained across messages, sessions, or tasks. |
| Policy | Rule that constrains behavior. |
| EvalGate | Check that decides whether work can complete. |
| Runtime | Where/how the harness executes. |
| PaymentIntent | Rail-neutral expression of spend or charge behavior. |
| Receipt | Evidence record for work, payment, or result. |
| ReputationSignal | Structured signal derived from behavior or verification. |
| Adapter | Code or mapping layer from ADL to a target provider/runtime. |
| Conformance | Degree to which an ADL file or adapter satisfies ReddiAgent rules. |
