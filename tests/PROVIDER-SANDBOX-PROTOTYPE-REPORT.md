# Provider Sandbox Prototype Report

_Anchor issue: #222._

## Scope

This report covers the first bounded provider-backed sandbox prototype.

The prototype uses a deterministic local fake provider adapter. It exercises provider-style prompt preparation, model metadata, budget checks, eval checks, and trace capture without making a hosted provider/model API call, reading credentials, using network access, invoking MCP, touching payment rails, running devnet, or running mainnet.

## Evidence

The evidence suite is generated by:

```bash
/Users/loki/.pyenv/versions/3.14.3/bin/python3 scripts/provider_sandbox_prototype.py
```

The pinned fixture is `tests/fixtures/provider-sandbox-prototype.json`.

Covered scenarios:

- `simple-agent-fake-provider-pass` runs `examples/simple-agent.yaml` through the local fake provider adapter and passes required budget and eval gates.
- `simple-agent-fake-provider-budget-fail` runs the same ADL/task with intentionally tight budgets and fails closed on prompt token, completion token, total token, and estimated cost gates while preserving eval pass evidence.

## Cost Evidence

The prototype records simulated token and cost metadata using deterministic local accounting:

- hosted provider calls: `0`
- external spend: `0`
- simulated estimated cost: recorded in `costEvidence.simulatedEstimatedCostUsd`
- pricing model: fake local USD `0.000001` per token for deterministic budget evidence

No real provider invoice, API usage, credential access, or external spend is produced by this lane.

## Trace Events

Each provider sandbox scenario emits:

- `provider.sandbox_started`
- `provider.prompt_prepared`
- `provider.response_received`
- `budget.checked`
- `eval.checked`
- `provider.sandbox_completed`

Prompt and response evidence is stored as hashes plus bounded previews. Secret values are not read and cannot appear in the fixture.

## Boundaries

The prototype evidence keeps these boundaries explicit:

- `providerSandboxExecutionAllowed=true`
- `hostedProviderModelApiCalls=false`
- `networkAccess=false`
- `credentialAccess=false`
- `paymentAccess=false`
- `mcpInvocation=false`
- `devnetAccess=false`
- `mainnetAccess=false`
- `externalSpendUsd=0`

## Decision

ReddiAgent now has a provider-backed sandbox surface that can prove provider-style budget/eval/trace behavior before any live provider adapter is introduced. A future live provider lane must keep the same evidence shape, add real provider usage/cost metadata, and fail closed under the same budget and eval gates.
